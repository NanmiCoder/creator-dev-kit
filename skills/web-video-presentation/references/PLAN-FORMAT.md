# plan.md 规格（规划阶段唯一产物）

`plan.md` 是整个项目**唯一的中间文档**：人读它对齐，`npm run gen` 读它生成
`src/registry/timeline.ts` + 各章 `narrations.ts` 骨架 + 各章 `BRIEF.md` 任务卡。
写完它 = 规划结束。不再写 outline / 章节 brief —— 那些由 gen 自动产出。
放在用户工作目录、与 `presentation/` 同级（gen 默认读 `../plan.md`）。

## timeline 块字段（gen 的机器输入，格式必须严格）

有且仅有一个 ` ```timeline ` fenced block，YAML 语法（两层列表 + 标量）：

| 字段 | 必填 | 说明 |
|---|---|---|
| `audio` | VO-First ✓ | 整段口播在 `public/` 下的相对路径。**原件先在 `public/` 之外另存一份（如 `presentation/audio-src/`），再拷副本进来 —— 任何工具都不碰原始录音** |
| `duration` | VO-First ✓ | `ffprobe -v error -show_entries format=duration -of csv=p=0 <mp3>` 实测秒数 |
| `parts` | 可选 | 补拍 / 分段录制的区间（`?auto=1&part=<id>` 只播该段）。省略 = 单区间全片 |
| `parts[].id / label / start / end` | — | 区间 id / 中文标签 / 绝对起止秒。start 必须落在某步 `at` 上（end 例外 = 区间最后一步的结束；贯穿到片尾的区间 end 写 `duration` 的值） |
| `chapters[].id` | ✓ | **小写 + 连字符**（`deepswe`、`skills-path`）。成为文件夹 `src/chapters/<NN>-<id>/`、React key、音频子目录 |
| `chapters[].title` | ✓ | 给人看的中文标题，不进代码 |
| `steps[].at` | VO-First ✓ | 该步绝对起始秒 = 该步第一条 SRT cue 的 start。**全局严格升序**（gen 校验，违规不写文件） |
| `steps[].vo` | ✓ | 该步覆盖的口播**原文**，多条 cue 用 ` / ` 连接。会原样进 `narrations.ts` —— 抄 SRT，别转写 |
| `steps[].do` | ✓ | 一句话画面创意。写"演什么"，不写实现手段 / 动画类型 —— 展开是章节 agent 的事 |

**TTS 路径**（只有文章、无录音）：同格式，`at` / `audio` / `duration` 全省略。
gen 跳过 timeline.ts，只出 narrations + briefs；音频走 `npm run extract-narrations`
→ `npm run synthesize-audio` 原流程，节奏以合成音频为准，step 数以 `narrations.ts` 为准。

## 切步与切章（经验，不是仪式）

- **SRT 先按 start 重排再用** —— 剪辑软件导出的 cue 编号常与时间乱序（结尾段
  编号反而排在文件开头）。只信时间戳，不信编号；乱序直接顺读会把结尾切进开头的区间
- **一步 = 一个聚焦想法**，3~10s。VO-First 直接照 SRT 的自然停顿切；步长 = 下一步 at − 本步 at
- **一章 = 一个聚焦主题**，3~8 步 / 30~60s（网页只占几段的补拍片里 10~30s 的短章也正常）。边界 = 讲者换气换话题的位置
- 估时用中文 ~4 字/秒（TTS 路径没有 at 时靠它规划节奏）
- `do` 只写一句（写死动画 = 章节 agent 退化成翻译机）；有更多方向想法，写进「章节画面备注」
- **整屏实测视频步**：vo 写 marker（如 `（整屏实测视频 · 任务①）`），timeline 里给 ~0.5s
  短区间，step 照占一格 —— 录制时一闪而过 = 后期插入实测视频的剪辑切点，音频照常连续播

## 事实核实协议（红线 —— 上屏内容必须过这关）

**凡是要上屏的数字 / 名称 / 排名 / 引用，必须在「事实核实记录」表里记齐三件事：
值 + 来源 + 核实方式。** 核实方式要具体到可复查：`原视频 mm:ss 帧（含表头）` /
`官方页 URL` / `用户口头确认`。写不出方式 = 没核实。

| 规则 | rationale |
|---|---|
| 表格 / 榜单数字必须**连表头（行名 + 列名）一起看到**才算核实；只看到数没看到归属 = 没核实 | 数字本身没有归属，归属才是最容易错的部分 |
| **推断 ≠ 核实**。凡靠推断得出的归属 / 数值，状态列必须写 `推断`，并在 checkpoint 显式列出请用户裁决 | 推断标成"已核实"，下游所有 agent 会放心引用，错误被复制进每份产物 |
| 口播与核实事实冲突时，**画面走事实 + 角注标口径**，不跟着口播错；冲突改写项与「推断」项一样**必须列进 checkpoint** | 口播已录死改不了，画面是唯一补救层。如画面写 `69` 并角注来源"DATACURVE 榜"（口播念的 60 观众会当约数）。但这是用户的片子 —— 改写口径要他点头 |

> **反例（375 期真实事故，本协议因它而生）**：口播念"Kimi K3 得到 60 分"。规划 agent
> 从视频帧里看到四个分数但**没看到表头**，按口播点名顺序推断 59.0 属于 Kimi K3，
> 标成「已核实」写进了所有文档。实际 59.0 是 Claude Opus 4.8 的分，Kimi K3 根本
> 不在那张表里（真实成绩 69 分，出自 Datacurve 榜）。错误被用户抓出，全链路返工半小时。
> 当时只要标一句「推断」，checkpoint 一问就拦下了。

## 禁上屏清单（VO-First）

- **禁把字幕 / 口播原文当屏幕文案整句搬上屏** —— 屏幕文案 = 口播的**子集 / 提炼**
  （关键词、数字、短语）。观众在听原声，不需要再读一遍
- 口播没说的梗 / 术语不留在屏幕上（稿子临场改过 → 屏幕跟最终 SRT，不跟旧稿）
- 口播真讲了的比喻 / 原话可以上屏强化
- 术语全片统一写法，锁进术语表；章节 agent 不得自创缩写

## 交 checkpoint 前自查（一分钟）

- at 全局升序、vo 与 SRT 逐字一致、parts 边界落在某步 at 上（gen 也会硬校验，先过一遍少跑一轮）
- 事实表无「推断」伪装成「已核实」；推断项与口播冲突改写项 → checkpoint 里单独列出请用户裁决
- 每条 `do` 你自己能想象出画面；想象不出 = 太空，补两句备注
