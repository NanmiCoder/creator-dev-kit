# Creator Pipeline 默认模板

运行 `npm run dev`，首页就是连续 MG 场景的逐拍演示。点击“下一步”或按 → / 空格推进；← 回退，“重播”回到开头。默认 creator-dark 主题。

- `/` 或 `?review=1&t=0&steps=1`：21 个动作拍，逐拍播放后停住。
- `?auto=1`：点击起播后，约 31 秒无声连播，到尾帧停止。
- `?manual=1`：点击舞台/方向键按六段口播推进，每段内部动作连续展开并停住。
- `?review=1&t=20`：确定性查看指定秒的画面，适合截帧。

舞台始终为 1920×1080 等比缩放。预览页右上角 **导出** 可选 1K / 2K / 4K MP4；录屏则框选 `.stage-frame` 的 16:9 内容区域。提示和控制条都在框外。小于 250px 高的窗口隐藏外部控件，可使用键盘。

未接入配音时，顶端会显示“模板演示 · 无声”，波形与时间区间为示意。模板不含个人录音，也不会请求不存在的音频、下载模型或自动调用付费服务。

## 用自己的内容制作

`src/chapters/01-pipeline/` 是默认场景的唯一实现：`chapter.tsx` / `chapter.css` 管构图与对象转换，`beats.ts` 管句内动作，`timing.ts` 管六段演示区间，`waveform.ts` 是可替换的示意波形。

1. 先准备最终音频与 SRT，导入并按内容写 `../plan.md`。然后 `npm run gen` 生成真实时间轴和章内 timing；整段音频以 `audio.currentTime` 驱动画面，无声预览不会覆盖真实音频失败。
2. 新文案需要新的章节、动作谱与画面。同步注册 `src/registry/chapters.ts`，移除默认注册的 `previewTiming`。不要只替换六句话却沿用不相干的“文案→声音→网页”镜头；动作数量按内容确定。

   **但“换内容”不等于“丢掉这套视觉语言”。** 两条路继承，都不靠手抄：

   - **卡片质感 → 用共享原语**：`src/styles/base.css` 已有 `.card`（`--surface-2` / `--bw-1 solid var(--rule)` / `--r-card` / `--card-shadow`），`App.tsx` 全局导入，任何章节直接可用。新卡片复用它加主题 token，**不要各章自创外观**。用 token 而非像素值 —— `01-pipeline` 里硬编码的 `border-radius:16px` 是没接上共享层的历史遗留，换主题会破，别照抄。
   - **动作编排 → 读 `beats.ts`**：16 行、中文标签、21 拍一目了然，是全套代码里唯一可读的规范文件。照它理解“一段口播拆几个动作拍、每拍的可见落点是什么”，再写自己这一章的 `beats.ts`。
   - **`chapter.tsx` 不要试图通读反推**：它是压缩写法（平均约 95 字符/行、仅 1 条注释、300+ 个数字字面量），里面的坐标是对着 1920×1080 逐像素调出来的，不可迁移。硬抄只会抄到字面（圆角、底色），丢掉节奏。

   换的是主体与文案，**不是质感**。`01-pipeline/` 目录保留作对照，不要删。
3. 若保留同名章节，注意 gen 会保留已有 `narrations.ts`，先备份并同步新稿。真实波形应从最终 PCM 提取，并将 `waveformIsIllustrative` 设为 false；没有实测波形就保留示意标注。
4. `npm run check`、`npm test`、`npm run build` 后，用本机可用浏览器检查逐拍、回退、连续播放和 16:9 框选边界。看片用 `?auto=1`，不加 review/mute。成片点右上角 **导出**。

保留已验收的构图层次、主体连续性、句内多拍推进与转场质量 —— 这几项是**必须继承的视觉语言**，新章节丢了它们就是返工。

六段故事和 21 拍则是这个演示的**内容编排**，不是其他题材的固定结构，按你自己的口播重写。两件事分开看：内容可以完全不同，视觉语言要一脉相承。
