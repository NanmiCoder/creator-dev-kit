# cc-haha 被说成木马：一条评论引出的 Agent 安全真相

## 01 开场 · 十几万人在用的项目，被说成肉鸡工厂（约 0:00–0:45）

我之前开源了一个基于 Claude Code 泄露源代码的桌面端 Agent cc-haha

支持 在macOS、Windows、Linux 上把它跑起来，同时对接了了多个Im聊天渠道

这项目开源到现在三个多月，GitHub 上一万三千多个 star，八千多次 fork。安装包累计下载了十一万多次——这个得说清楚，我已经迭代了快三十个版本了

就这么个玩意儿，今天又有人在我评论区留了一条，我原文给你念一遍，一个字没改：

「不要下，里面有木马，而且你的机器会变成肉鸡，ip更是全暴露，他可以随意安装其他木马进去，

你家的wifi网络连接到的设备都会中毒，并且你的支付系统会在他的眼皮子底下支付，密码他分分钟能获取到。」

我看到这条评论瞬间就来气了，好家伙

我免费开源这样一个软件一个这么多人在用、代码全公开摆在 GitHub 上的开源项目

就被我顺手就把你家路由器、你连的 WiFi、连你的支付密码，全给端了。

## 02 不是第一次 · 木马替我给女同学表白（约 0:45–1:20）

而且这还真不是第一次。当初我刚把 cc-haha 开源出来那会儿，就有人说我项目里植入了木马，关键这木马还挺忙

说是控制了他的聊天软件，替他给女同学自动发消息表白去了。

我当时人是懵的，啊？我一个开源仓库，跨过 Electron、穿过你的网卡、钻进你的微信，替你搞对象去了？

我要是真有这本事，我还开什么源，直接开婚介所了。

行，玩笑归玩笑。你说项目有 bug，你说某个功能不好用，你说哪个设计有安全隐患，这些我都接，我改就是了。

可上来两个字就是木马，然后肉鸡、WiFi 中毒、支付密码，一股脑全塞进一个锅里，锅盖上还替我写好了仨字——cc-haha。

这我是真不知道从哪儿辩解。

当时这个表白女同学的哥们，他说，他在电脑上用360 扫了一下，报了毒。

但这就是个误报，原因很简单：Windows 版现在没做签名，加上它有个 Computer Use 功能，能帮你截屏、点鼠标、敲键盘——这几个动作，在杀软眼里跟远控木马长得太像，启发式引擎一看，啪，直接标红。跟有没有毒，没关系。

而且我压根不想在这上面解释太多。

你想啊，cc-haha 代码全部开源，摆在 GitHub 上三个多月，一万三千多个 star、八千多次 fork 盯着看。

真要藏了木马，早被人扒出来、挂着骂了

所以报毒这事翻篇。真正值得聊的，是另一件很多人根本没搞清楚的事。



## 03 别搞混 · 漏洞、投毒，不等于埋木马（约 1:50–2:30）

但是 Agent 这东西真正的风险很大是在其他地方

cc-haha 是个 Electron 桌面端，底下确实依赖一堆第三方 NPM 包，axios、execa、node-pty 这些，现代软件谁都绕不开。

而这类上游的包被投毒，是真发生过的事——Axios 那种量级的包被投过毒，
Apifox 出过发布链路的事，
连 Codex 这种大厂官方 Agent 都披露过沙箱边界的坑。

所以供应链也是存在潜在风险的，这点我从来不否认

但我们得把两件事分清楚：一个项目有漏洞、供应链被人投毒，跟作者故意埋木马坑你，完全是两码事。

前者是我踩了别人埋的雷，后者是我亲手给你挖坑。你把这俩搅一块儿，什么都往「有木马」上一推，那才是真冤枉人。

那评论里说的那些吓人场面，万一真出了，锅该谁背？我跟你讲，最大的嫌疑，根本不在 cc-haha 身上。

## 04 命门在上游 · 是谁把那条 bash 递到你手上（约 3:10–4:10）

你得先知道 Agent 是怎么干活的。它自己不思考，每走一步都在听上游那个大模型的话。

模型给它返回内容，这返回里经常就夹着一句「你去把这条命令跑一下」，很多时候就是一条 bash。

Agent 拿到手，二话不说就真给你执行了。要命的地方就在这儿——要是这条命令是让它上网拉一个安装脚本、拉个不明来路的二进制回来跑，而返回这段内容的上游，恰好被人动过手脚，那木马就这么大摇大摆进来了。

看清楚了啊，这跟 cc-haha 本体干不干净，一毛钱关系都没有。真正的命门是，这条命令到底是谁递到你手上的。

你用官方模型，这条链相对是干净的。可现在好多人图便宜，群里随手转来一个中转站地址就往上接，价格低到不正常，注册还白送你一堆额度，网站上连个公司主体都查不到，服务协议、隐私说明啥都没有，你甚至不知道自己的请求最后被转到哪儿去了。你把一个能读你文件、能跑命令、能联网下东西的 Agent，稳稳当当接到这么个黑箱上，它理论上就能影响模型返回给你的内容，反过来诱导你的 Agent 去跑一段危险命令。

真出这种事，大概率就出在这儿。你把这套逻辑原封不动套到 Claude Code、Codex、Cursor 上，一模一样。随便哪个 Agent，只要它闭着眼睛信任上游返回的东西，照样中招。这不是哪个项目的锅，这是「你到底信了谁」的锅。所以「这个开源项目有木马」这句话，方向从一开头就是错的，你顺着它查，永远查不到真问题在哪。

## 05 另一条线 · Skill 投毒，你可能连看都没看（约 4:10–5:00）

而且上游模型只是其中一条线。还有一条，很多人栽得更惨，就是 Skill。

现在的 Agent 基本都能装 Skill、装插件、接 MCP。大家心理上都觉得，这不就是个提示词包嘛——装一个能帮我剪视频，装一个能帮我爬数据，装一个能自动部署，真香。群里谁甩个压缩包过来，说这个 Skill 好用，你解压完想都不想就往主力环境里塞。

但你得换个眼光看它。在 Agent 时代，Skill 别当提示词看，你得把它当代码看。因为它能实打实地指挥你的 Agent 去读哪些文件、跑哪些命令、连哪些服务。有些 Skill 里就明晃晃写着工作流、写着要执行的命令、写着让 Agent 去联网下载装某个依赖。那要是这个 Skill 本身就被投了毒呢？要是它里头夹了一段你压根没留意的危险指令呢？它又不是官方来的，就是群里随手转的一个包，你把它喂给一个能读文件、能跑命令的 Agent，最后出了事，你还回头怪那个开源软件有毒。

所以那种来路不明、还会跑命令、会联网、会读文件的 Skill，别直接往你天天干活的环境里塞。你最起码打开扫一眼；看不懂，就先丢到一个隔离环境里跑。别把它当成一个人畜无害的文档。

## 06 能存下来的建议 · 你到底在信任谁（约 5:00–5:40）

那我直接给你一个能存下来的建议。用大模型，最省心的就是走国内官方的；实在非要用中转站，就挑那种公司主体在国内、正经运营、体量也还看得过去的，别碰那种今天上线、明天跑路的野站；你要是用国外模型，那就走国外官方。道理很朴素，不是说哪个就绝对安全，而是至少你清楚自己在信任谁，真出了事，你也知道该去敲谁的门。这比省那仨瓜俩枣，重要太多了。Skill 和插件也一样，官方的、有人在维护的、大家都在用的，你放心装；来路不明的，先隔离跑，别直接上主力机。

我也不是让你无脑信 cc-haha。开源项目就该被人看、被人审、被人质疑，这没毛病，我代码全摆在那儿，一分钱没收过你的，你尽管扒。但你质疑，能不能带点证据、讲讲链路？把你用的 Provider、base URL、跑的哪个模型、装过啥、执行过哪几条命令，往评论区一贴，大家当场帮你一起看到底哪一环烂了，这叫技术讨论。你就甩俩字木马，听着是挺唬人，可对排查是真一点用都没有。

说到底，在 Agent 时代，你真正选的，从来不是一个便宜三块钱的中转站——你选的，是把自己的大脑，外包给一个你根本不认识的人。
