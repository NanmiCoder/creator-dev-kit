# Case 02｜实时运营后台：POLARIS 冷链运控中心

## 你的任务

请在当前项目中直接实现一个可运行的 **POLARIS 冷链运输实时运控后台**。使用者是正在值班的物流调度员，需要同时判断车辆位置、温控风险、延误订单和待处理事件。

这是一个真实业务工具，不是几张数据卡片拼出的 Dribbble 概念图。它必须在高信息密度下依然精致、清楚、可操作，同时具备电影级的暗色界面、Liquid Glass 悬浮层和细腻的实时动效。不要向我提问，合理补全细节并直接实现。

## 视觉与信息架构

- 采用 **炭灰 / 冷灰底色 + 单一低饱和琥珀色状态强调**。冷链地图本身可以使用灰蓝水域，但紫色、蓝紫渐变、赛博霓虹与纯黑全部禁用。
- 视觉概念是“凌晨 02:17 的专业运控室”：安静、精密、可信，而不是游戏 HUD。
- 字体使用 `Geist + Geist Mono`、`Satoshi + JetBrains Mono` 或同等级组合；所有数字、时间、温度和编号统一使用等宽字体。禁止 Inter、衬线字体和 Emoji。
- 页面主体是一张全幅的长三角运输网络地图，界面层像仪器一样悬浮其上。高层级面板使用具有内高光、折射边缘、轻微染色和景深的 Liquid Glass；普通数据区域用细分割线、留白和排版组织，禁止把每一项都塞进圆角卡片。
- 设计应高密度但不拥挤，至少存在一个明确的非对称构图和一个会随状态变化的动态岛式区域。

## 必须实现的界面

1. 左侧窄导航栏：总览、车队、订单、温控、异常、报表、设置；悬停时图标与标签有顺滑展开效果。
2. 顶部状态条：
   - 当前班次 `夜班 · 20:00—08:00`
   - 系统时间 `02:17:43`
   - 在线车辆 `184 / 191`
   - 一个会在“正常 / 风险 / 处理中”之间形变的动态岛。
3. 中央实时地图：
   - 用 SVG 或 Canvas 自绘具有设计感的区域路网，不依赖地图 API。
   - 显示上海、苏州、杭州、宁波、嘉兴等节点、运输线路和 12 辆代表车辆。
   - 车辆沿路线缓慢移动；选中车辆后路线高亮，其他信息降噪。
   - 鼠标悬停显示玻璃浮层，包括车牌、司机、货物、实时温度、预计到达时间。
4. 左上关键指标区：准点率 `93.7%`、运输中 `128`、温控风险 `7`、今日里程 `18,642 km`。指标不要做成四张相同卡片。
5. 右侧事件流：至少 6 条具备真实细节的事件，例如：
   - `沪AD·6832` 冷藏厢温度在 11 分钟内由 `3.8°C` 升至 `7.1°C`
   - `P-240821-0719` 因 G60 拥堵预计延误 `26 min`
   - 嘉兴南仓 `Dock 07` 装卸等待超过 SLA `14 min`
6. 底部可折叠车队表格：车辆、司机、路线、货物、温度、ETA、状态；支持排序、状态筛选和搜索。数据要自然、参差、可信，禁止整齐的假数字和 John Doe 类占位姓名。
7. 车辆详情抽屉：点击地图节点或表格行后从右侧展开，展示温度折线、路线进度、货物批次、司机联系信息和 `标记已处理` 操作。
8. 快捷指令面板：按 `/` 或 `Cmd/Ctrl + K` 打开，可搜索车辆、订单或执行“只看温控风险”。

## 真实交互与状态

- 搜索、筛选、表格排序、地图选择和详情抽屉必须共享同一份前端状态并真实联动。
- 点击事件流中的异常，地图应聚焦对应车辆并自动打开详情；点击“标记已处理”后，事件状态、计数和动态岛同步变化。
- 提供一个不抢视觉焦点的 `Demo State` 控制入口，可以切换正常、加载中、空数据和接口错误四种状态，以检查骨架屏、空状态与内联错误设计。
- 列表进入使用瀑布式编排；状态变化使用 layout/shared-element 过渡；弹层和抽屉采用有重量感的 spring，而不是线性位移。
- 仅将呼吸点、车辆移动等少数“实时信号”做持续动画，所有持续动画必须隔离并避免父组件重渲染。
- 所有操作具有 hover、active、focus-visible、disabled 状态；键盘导航和 Escape 关闭弹层可用。

## 工程约束

- 使用 React + TypeScript；优先复用现有项目技术栈。先检查 `package.json` 再决定是否安装 Framer Motion、图表或图标依赖。
- 如使用 Tailwind，必须确认版本并采用对应语法。组件库可以使用，但必须彻底重设色彩、圆角、阴影和交互，不能保留默认外观。
- 地图与图表不得只是静态背景图；使用 SVG、Canvas 或轻量图表库实现可交互的数据表达。
- 动画只改变 transform 与 opacity；对持续动画和计时器做好清理。噪点只放在固定且 `pointer-events: none` 的覆盖层。
- 桌面以 1440px 为主要展示宽度，同时在平板和手机上转为“地图 + 底部抽屉”的稳定布局。不得使用 `h-screen`，使用 `min-h-[100dvh]`，不能横向溢出。
- 禁止 Emoji、Unsplash、伪代码、TODO、不可用按钮和纯静态 mockup。

## 完成标准

最终交付可直接运行的完整后台。它应让人第一眼感到“非常酷”，第二眼能快速读懂风险，第三步可以真正完成搜索、筛选、定位与处理异常。视觉效果、信息密度、Liquid Glass 材质和业务交互缺一不可。
