# Case 03｜3D 数字孪生控制台：PELAGOS 海上风场

## 你的任务

请在当前项目中从零设计并实现一个可运行的 **PELAGOS 海上风电数字孪生控制台**。用户是海上风场运维工程师，需要在真实可交互的 3D 场景中巡视风机、查看功率与告警、回放天气，并制定维护任务。

这是最高难度 case。最终成果应该像一套真正进入指挥中心的大屏产品，又像一次电影级产品演示：全屏实时 3D、层次分明的 Liquid Glass 操作层、镜头叙事、复杂状态联动和可靠的性能策略都必须存在。不要停留在概念说明，不要向我提问，直接完成。

## 核心视觉概念

- 场景设定为“日落后 18 分钟的北海”：深灰蓝海面、残留天光、低云、远处薄雾与风机红色航标灯。界面使用石墨灰与雾银，唯一强调色为低饱和安全橙。
- 禁止紫色/蓝紫 AI 渐变、纯黑、电竞霓虹、廉价外发光、渐变大标题、Emoji 和 Inter 字体。
- 3D 场景是视觉主体，UI 不是四周贴满面板，而是少量高价值仪器层悬浮其上。面板必须具有真实 Liquid Glass 观感：透明层次、背景折射、1px 内高光、边缘明暗变化、细腻内阴影、面板重叠时可信的景深。
- 使用 `Geist / Satoshi` 搭配 `Geist Mono / JetBrains Mono`；数字、坐标、功率和时间统一等宽。
- 视觉变化度 9/10、动效强度 9/10、信息密度 7/10：大胆、流畅、复杂，但不能牺牲可读性。

## 必须实现的真实 3D 场景

- 使用 Three.js 或 React Three Fiber 构建真正的 WebGL 场景，禁止用 2D 图片、视频或 CSS 假装 3D。
- 程序化生成至少 24 台海上风机，包含塔筒、机舱和三片叶轮；使用 InstancedMesh 或等效优化，不依赖外部 GLB 才能运行。
- 海面必须有缓慢起伏、反射或着色器层次；加入雾、天空渐变、主光源和远处风场层次。控制效果开销，不要堆叠昂贵后期。
- 每台风机具有独立状态：正常、限功率、离线、待维护。叶轮转速需与当前风速/状态关联，而不是所有实例完全同步。
- 支持旋转、平移、缩放；悬停风机时出现克制轮廓和编号，点击后镜头平滑飞近。飞近时浮出该机组的玻璃数据铭牌，退出后镜头回到风场总览。
- 进入页面时设计一段 3—5 秒可跳过的镜头序列：掠过海面、穿过第一排风机、最后停到运维视角。不能用突兀 cut，也不能让动画阻塞页面操作。

## 操作界面

1. 顶部导航：`PELAGOS / FIELD 07`、当前时间、风速、并网功率、连接质量，以及会在告警出现时形变的动态岛。
2. 左侧资产树：A、B、C、D 四个阵列和 24 台风机；支持搜索、折叠、状态过滤。点击条目必须与 3D 选中状态双向同步。
3. 右侧上下文面板：默认展示风场功率、利用率和今日发电量；选中风机后切换为该机组的实时功率、机舱温度、振动、偏航角和最近工单。面板内容使用 shared layout 平滑变形，不整块闪切。
4. 底部时间轴：可拖动回放最近 12 小时天气。时间变化时，风速、海浪幅度、天空明暗、风机转速、总功率和告警记录同时更新。
5. 视图模式：`现场`、`功率热力`、`维护风险`。切换到热力模式后，风机必须按真实数值形成可读的空间编码，并显示图例。
6. 告警中心：包含 `T-18 齿轮箱振动 8.7 mm/s`、`T-07 偏航误差 11.4°`、`T-22 SCADA 信号中断 03:42` 等自然数据。点击告警会定位机组、切换视图并打开上下文面板。
7. 维护任务流：从风机详情点击 `创建维护任务`，由原按钮自然 morph 成玻璃任务面板；可以选择时间、严重级别与技师，并完成提交中、成功、错误状态。
8. 提供一个电影模式：收起大部分 UI，镜头沿预设路径巡视风场；用户任意交互后立即、平滑地退出电影模式。

## 交互、动效与声音感

- UI 弹层、选择、过滤和重排使用有重量的 spring 动画；同类元素使用 layout/shared-element 过渡。
- 允许少量常驻微动效，例如航标灯、连接呼吸点、海浪和数据流，但每个持续动画都应有明确意义。
- 玻璃按钮具备方向感 hover、按压回弹和清晰 focus-visible；桌面端主要 CTA 可实现磁吸微物理，但不能用 React state 驱动连续指针动画。
- 提供完整的 loading、empty、WebGL 初始化失败和数据错误状态。WebGL 失败时显示设计完整的降级总览，而不是白屏。
- 支持 `prefers-reduced-motion`：关闭自动巡航与强视差、缩短镜头移动，但不能破坏功能。
- 支持键盘选择、Escape 返回总览、`F` 聚焦机组、`M` 进入/退出电影模式；在界面中以不打扰的方式提示快捷键。

## 工程与性能要求

- 使用 React + TypeScript。先读取 `package.json` 并验证依赖；缺少 Three.js、React Three Fiber 或动画库时再安装并说明，不得假设依赖存在。
- 不要在同一组件树里混用 GSAP 与 Framer Motion。3D 渲染循环、UI 动画和应用状态需要清晰分层。
- 使用单一状态源保证资产树、3D 选择、告警、时间轴、详情面板和维护表单一致；避免不必要的全局状态。
- 限制设备像素比，在移动设备下降低海面与阴影质量；不可见标签页暂停非必要动画；正确清理 RAF、监听器、材质、几何体与 WebGL 资源。
- 目标为主流笔记本稳定接近 60fps。不得通过删掉核心 3D 与联动来换取流畅。
- 桌面是主要体验，但平板和手机也必须可用：小屏把资产树和详情改为底部玻璃抽屉，保留选中、时间轴与视图切换。使用 `min-h-[100dvh]`，禁止横向滚动。
- 不要使用易失效的外部资源、Unsplash、伪代码、TODO 或不可用按钮。

## 完成标准

最终交付的是一个可运行、可操作、具有真正 3D 深度的数字孪生产品。验收时会实际点击风机、拖动时间轴、切换热力模式、从告警定位资产并创建维护任务，同时观察玻璃材质、镜头语言、状态一致性、移动端与帧率。任何仅有静态大屏外观、没有交互闭环或用图片冒充 3D 的实现都视为未完成。
