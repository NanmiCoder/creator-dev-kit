## 01. 成果钩子：这不是传统 PPT

**录制目标**：前 20 秒先把观众抓住，让他们知道“这条视频本身就是样片”。  
**网页 PPT 画面方向**：大标题“这条视频不是 PPT”；旁边展示网页舞台、音频波形、SRT 时间轴、录屏框四个元素。  
**后期补充**：插入 2-3 个往期成片或当前网页 PPT 效果片段，每段 2 秒即可。

**口播正文**：

你现在看到的这条视频，其实不是传统 PPT 剪出来的。

它是一个网页。

跟着我的口播音频和字幕时间轴自动播放。

最后我只是把浏览器录下来。

最近很多人在我评论区问：

你这几期视频是怎么做的？

动画效果是怎么弄的？

今天这期，我就把这套 workflow 从 0 到 1 拆给你。

不是只讲概念。

我会把口播稿、音频、SRT、网页 PPT、页面 review、最后录屏，完整过一遍。

大家可以先个关注收藏起来慢慢看

## 02. 普通创作者痛点

**录制目标**：把技术问题翻译成普通创作者能感知的麻烦。  
**网页 PPT 画面方向**：四个痛点逐个出现：PPT 难看、动画费时间、录制卡壳、字幕返工。  
**后期补充**：不需要实录。

**口播正文**：

如果你也做知识科普、技术教程、AI 工具分享，这套方法会很适合。

因为这类视频最麻烦的地方，其实不是讲观点。

而是后面那些苦活。

PPT 一页页做。

动画一段段拖。

自己对着现成PPT录的时候还容易卡壳。

剪完以后发现字幕对不上，又要返工。

所以我现在的思路是：

先把声音和时间轴定死。

再让 Agent 按这个时间轴去做画面。

最后统一录屏成片。

## 03. 五步工作流公式

**录制目标**：给观众一个可收藏、可复述的主公式。  
**网页 PPT 画面方向**：横向时间轴：口播稿 -> 音频 -> SRT -> 网页演示 -> 录屏成片。  
**后期补充**：不需要实录。

**口播正文**：

整条链路就五步。

先有口播稿。

再有口播音频。

再有 SRT 字幕时间轴。

再让 Agent 做一个 16:9 的网页演示。

最后用录屏软件录下来。

它看起来像 PPT。

但底层不是 PPT。

它就是一个前端项目。

由 HTML、CSS、JavaScript 这些东西构成。

页面跟着口播节奏切换。

动画也跟着字幕时间轴走。

这就是我最近几期视频的核心做法。

## 04. 为什么自然带出 MiniMax Code

**录制目标**：降低硬广感。先说 workflow 需要什么，再说 MiniMax Code 为什么顺手。  
**网页 PPT 画面方向**：左侧“这套方法不绑定工具”，右侧“桌面端 Agent 适合串本地文件”。  
**后期补充**：可补 MiniMax Code 主界面 3-5 秒，不需要长录。

**口播正文**：

这里先说清楚。

这套方法不绑定某一个Agent工具。

你用国外的Claude Code、Codex、Cursor

国内的MiniMax Code、Trae、Zcode这些都可以做

今天我们实战演示环节涉及TTS音频生成、还有多模态理解

所以我这期用 MiniMax Code 来演示。

它在这个场景里比较顺手。

不是因为它是什么万能神器。

而是因为这种知识科普视频制作类任务，本质上更多是页面、布局、动画、节奏，不是特别极限的后端研发。

没必要每一步都用最贵的模型。

对于我们这种需要大量Agent协作的任务，MiniMax Code桌面端中MiniMax M3模型推理能力完全足够且性价便宜

## 05. 先做口播、音频、SRT

**录制目标**：强调先录 MP3 / 先做 SRT 的必要性。  
**网页 PPT 画面方向**：音频波形 + SRT 时间戳逐行点亮。  
**后期补充**：必须补 SRT 文件时间戳镜头，这是最重要证据之一。

**口播正文**：

下面正式开始。

第一步，不是做画面。

先做口播。

我建议大家一定先把口播稿和音频解决掉。

因为口播是整个视频的骨架。

你自己都还没确定要讲什么，后面做再多动画都是返工。

如果你愿意自己录，就像我平时一样，先录一段音频。

然后在剪映或者其他工具里把字幕导出来。

如果你暂时不想自己录，也可以用 TTS。

本期为了演示方便，我会直接让 MiniMax Code 生成一份口播音频。

然后再把这段音频转成 SRT。

这个 SRT 非常关键。

因为它里面有时间戳。

后面网页什么时候切页，什么时候出动画，什么时候停留，都要靠它来对齐。

你可以把 SRT 理解成整条视频的节拍器。

先别急着做页面动画效果这些。

口播和时间轴不稳，后面全是返工很难受。

## 06. 安装两个 Skill

**录制目标**：讲清两个 Skill 的职责，不把工具列表讲成广告。  
**网页 PPT 画面方向**：三方分工图：设计审美、网页视频结构、本地执行链路。  
**后期补充**：可补 slash command 出现两个 Skill 的镜头。

**口播正文**：

第二步，准备两个 Skill。

一个是 leonxlnx/taste-skill 这个开源仓库。

这期实际会用它里面的 design-taste-frontend。

它主要负责提升前端页面的设计品味，避免 Agent 做出来的东西太像普通模板。

另一个是花园老师开源的ConardLi/garden-skills

我们会用到它里面的web video presentation。

它负责把文章或者口播稿，做成点击驱动的 16:9 网页演示。

在 MiniMax Code 里，你直接把这两个开源 Skill 地址给它。

然后用自然语言说：

帮我安装这两个 Skill。

安装完成之后，斜杠命令里能看到，就说明已经装好了。

这一步不用记复杂命令。

你真正需要理解的是：

design-taste-frontend 管审美。

web video presentation 管网页视频结构。

MiniMax Code 负责把本地文件、音频、SRT、网页项目和 review 串起来。

## 07. 先做第一章，不要一口气做全片

**录制目标**：告诉观众第一个验收节点在哪里，减少后期返工。  
**网页 PPT 画面方向**：第一章作为“风格锚点”，旁边列验收指标。  
**后期补充**：必须补 localhost 第一章预览镜头。

**口播正文**：

第三步，把口播稿、音频和 SRT 交给 web video presentation。

这里不要一上来就让它做完整条视频。

我现在更推荐先做第一章。

因为第一章就是整条片子的风格锚点。

先看它像不像视频。

看画面是不是太像普通 PPT。

看信息是不是太满。

看转场是不是太重。

看字体、颜色、节奏是不是舒服。

第一版肯定不会完美。用自然语言交互打磨就好了

这很正常。

## 08. 第一版问题与自然语言修改

**录制目标**：增加“真实跑通过”的可信度。  
**网页 PPT 画面方向**：左边“不满意反馈”，右边“修改后效果”。  
**后期补充**：建议补一个真实问题：文字太满、太像 PPT、转场太重、文字溢出。

**口播正文**：

比如你可以直接说：

这个太像普通 PPT 了。

这一页文字太满了。

这个转场太重了。

这里不要堆那么多信息。

让它改到第一章能看，再继续做后面。

精彩的地方在这里。

它不是在做传统 PPT。

它是在按你的字幕时间轴写网页。

所以你后面看到的每一页，本质上都是一个网页状态。

## 09. AgentTeams 并行做完整页面

**录制目标**：自然展示 MiniMax Code 的 AgentTeams，而不是生硬卖点。  
**网页 PPT 画面方向**：一个总脚本拆成多个章节，每个 Agent 负责一块。  
**后期补充**：可选补 AgentTeams 分工界面，不是必须。

**口播正文**：

第四步，第一章确认以后，再做完整项目。

这个时候就可以用 MiniMax Code 里的 AgentTeams。

也就是多个 Agent 协作。

每个 Agent 负责一段章节。

这一段做开头。

那一段做工具链。

另一段做 review 和录屏。

最后再把所有章节合起来。

这类网页 PPT 很适合这样拆。

因为每一章相对独立。

主要工作是页面、动画、布局、节奏。

不是那种必须一个人从头到尾盯着的复杂后端系统。

所以这里也能自然体现 MiniMax Code 的价值。

它不是只帮你回答问题。

它是在本地帮你组织一条生产线。

## 10. 多模态 Review

**录制目标**：强调“生成完不能直接录”，展示质量控制。  
**网页 PPT 画面方向**：Review 清单逐条点亮：文字、布局、风格、信息密度、服务口播。  
**后期补充**：建议补截图 review，并展示一个真实问题被指出。

**口播正文**：

第五步，做完以后不要直接录屏。

一定要 review。

因为网页 PPT 最容易出的问题，不是代码跑不起来。

而是画面不够舒服。

比如文字溢出。

比如某一页太满。

比如动画挡住字幕。

比如主题风格前后不统一。

比如画面只是把口播文字打了一遍，没有服务内容。

这些问题，人当然可以一页一页看。

但如果让 AI 自己检查，它就需要视觉理解。

所以这里我会用多模态 review。

花园老师的这个SKILL中就自带Review的指令约束了

把页面截图给模型。

让它看布局、文字、风格、信息密度。

如果它指出哪一页有问题，就先修掉。

修完以后，再开始录屏。

这一步很重要。

不要相信“生成完就能录”。

真正省时间的，不是一次生成完美。

而是它发现问题以后，能快速改到能录。

## 11. 自动播放与录屏成片

**录制目标**：闭环证明整个流程真的能生成视频。  
**网页 PPT 画面方向**：录屏前检查页：localhost、auto mode、16:9、系统声音、按空格。  
**后期补充**：必须补最终 auto 播放 + 录屏软件 10-20 秒。

**口播正文**：

最后一步，就是预览和录屏。

打开本地预览地址。

开启自动播放模式。

录屏软件选中 16:9 区域。

录制系统声音。

然后按空格开始播放。

这个时候，网页在播放。

音频在播放。

动画也跟着字幕时间轴走。

你把这个过程录下来，整条视频就出来了。

这种方式最大的好处，是稳定。

你不用一边翻页一边临场发挥。

也不会讲到一半突然忘词。

因为声音已经定好了。

时间轴已经定好了。

画面只是按照它往前走。

如果你后期想露脸，也可以把自己的人像抠出来，叠到网页 PPT 上面。

这样看起来就像是人在讲解这个动态 PPT。

## 12. 适用人群与边界

**录制目标**：避免把方法吹成万能，建立可信边界。  
**网页 PPT 画面方向**：适合 / 不适合双栏对比。  
**后期补充**：不需要实录。

**口播正文**：

当然，这套方法不是适合所有视频。

如果你是强真人表达，或者情绪型 vlog，就不一定合适。

但如果你做的是知识科普、技术教程、AI 工具分享、产品演示，它就很适合。

因为这些内容更需要结构化展示。

更需要电脑画面。

也更适合被拆成一页一页的视觉节拍。

## 13. 结尾 CTA

**录制目标**：给观众明确下一步，让评论区能接话。  
**网页 PPT 画面方向**：三步试跑清单：60 秒口播、SRT、第一章预览。  
**后期补充**：不需要实录。

**口播正文**：

最后再总结一下。

这期不是教你写前端。

也不是说 MiniMax Code 是唯一选择。

真正重要的是这个流程：

先把口播定下来。

再把音频和 SRT 定下来。

再让 Agent 按时间轴做网页 PPT。

再用多模态 review 检查每一页。

最后自动播放录屏成片。

会做视频的人，未来不一定是一页一页拖动画。

而是把自己的创作流程搭成系统。

你可以先拿一条 60 秒口播试一下。

不要一上来做完整长视频。

先跑通音频、SRT、第一章预览这三件事。

如果这三步通了，后面扩成完整视频就只是时间问题。
