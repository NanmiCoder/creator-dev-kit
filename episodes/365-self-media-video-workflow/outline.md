# 网页视频开发计划

> 主题：`midnight-press` 暗色印刷。  
> 开发模式：先做第 1 章作为风格锚点，用户 review 后再继续后续章节。  
> 音频模式：VO-First，使用整段 `音频部分.mp3`，按 SRT 绝对时间点推进页面。

## 01-hook · 成果钩子：这不是传统 PPT

信息池：
- SRT cue 1-20，时间范围 `00:00:00.033` 到 `00:00:29.533`。
- 章节核心不是解释工具，而是先让观众看见“这条视频本身就是样片”。
- 画面需要展示网页舞台、口播音频、字幕时间轴、浏览器录屏、完整制作链路。
- 第一章不需要真实软件实录，先用高质量 UI 模拟“网页视频生产线”；后续可插入真实录屏素材。

Step 切分：

1. 反差对照：观众看到的不是传统 PPT 剪片，而是一条网页视频。
2. 本体揭示：它是一个网页，底层是浏览器里的 16:9 舞台。
3. 时间轴驱动：口播音频和 SRT 时间戳负责自动播放。
4. 录屏成片：最后只是把浏览器录下来。
5. 评论区问题：观众问“视频怎么做，动画怎么弄”。
6. 从 0 到 1：本期不讲概念，而是拆整套 workflow。
7. 完整链路：口播稿、音频、SRT、网页 PPT、review、录屏完整过一遍。
8. 收藏收束：提示先关注收藏，后面慢慢看。

素材清单：
- 已有整段口播：`音频部分/音频部分.mp3`
- 已有 SRT：`音频部分/音频部分.srt`
- 已有本地素材视频：`素材/IMG_6164_clean.mp4`，本章暂不直接嵌入，后续作为实录或成片快切素材候选。

## 02-positioning · 适合谁，为什么用 MiniMax Code

信息池：
- SRT cue 21-52，时间范围 `00:00:29.600` 到 `00:01:21.200`。
- 本章先回答“这套方法适合谁”，再自然引出“本期为什么用 MiniMax Code 演示”。
- 重点不是给工具打广告，而是把工具选择放在场景需求里：TTS 音频生成、多模态图片理解、页面理解、布局、动画节奏、大量 review、多 Agent 协作。
- 需要强调方法不绑定某个 Agent 工具；Claude Code、Codex、Cursor、MiniMax Code、Trae、Zcode 都可以做。

Step 切分：

1. 适用人群：知识科普、技术教程、AI 工具分享三类内容进入适配区。
2. 不绑工具：workflow core 在中心，工具名退到外围。
3. 工具横向展开：国外与国内工具双列呈现，MiniMax Code 只是本期演示对象。
4. 本期选择理由：TTS 音频生成 + 多模态图片理解是关键需求。
5. 任务本质：页面理解、布局、动画节奏，不是极限后端研发。
6. 成本/能力平衡：没必要每一步都用最贵模型。
7. Review 协作：后面大量效果 review 需要多个 Agent 分流。
8. 结论盖章：MiniMax M3 + AgentTeams 能 cover 当前开发需求。

## 03-voice-srt · 第一步：先定声音和时间轴

信息池：
- SRT cue 53-84，加上排序异常的 cue 219；真实时间范围 `00:01:21.300` 到 `00:02:08.133`。
- cue 219 在原 SRT 文件末尾，但时间是 `00:01:23.666`，必须插在 cue 54 后、cue 55 前。
- 核心观点：第一步不是做画面，而是先做口播、MP3 和 SRT，因为口播是整个视频骨架。
- 可以真人录，也可以用 MiniMax 的音频能力先克隆音色，再用逐字稿生成 MP3，并转成带时间戳的 SRT。

Step 切分：

1. 正式开始：第一步不是做画面。
2. 先做口播：排序后的 cue 219 单独强调，音频轨点亮。
3. 口播是骨架：口播稿和音频撑起网页舞台。
4. 不想真人录：MiniMax 音色克隆 / 音频能力作为可选路径。
5. 逐字稿生成 MP3：文案文件进入音频渲染队列。
6. MP3 转 SRT：波形被切成一行行 timecode。
7. 后续方便：有 MP3/SRT 后，网页怎么做都更容易；无 Skill 可做但调很多。

## 05-first-anchor · 第三步：先做第一章风格锚点

4. 验收扫描：像不像视频、普通不普通、信息密度、转场、字体颜色节奏逐项扫描。

## 06-agentteams-parallel · 第四步：AgentTeams 并行做完整项目

信息池：
- SRT cue 138-161，时间范围 `00:03:24.833` 到 `00:04:05.433`。
- 第一章确认后再做完整项目，这时使用 MiniMax Code 的 AgentTeams。
- 每个 Agent 负责一段章节：开头、工具链、review、录屏等，最后把所有章节结合起来。
- 网页 PPT 适合并行拆分，因为章节相对独立，主要工作是页面、动画、布局、节奏，不是强耦合后端系统。
- 这里要自然体现 MiniMax Code 的价值：不是简单问答，而是在本地组织一条生产线。

Step 切分：

1. 任务板解锁：第一章确认完成后，完整项目开始。
2. AgentTeams 出场：多 Agent 协作进入工作台。
3. 多泳道分工：每个 Agent 负责不同章节段落。
4. 汇入 presentation：独立 chapter folder 汇入总项目。
5. 适合拆分：章节隔离、CSS 前缀、页面动画布局节奏独立推进。
6. 本地生产线：MiniMax Code 不是问答，而是在本地组织文件和任务。
7. 进度汇流：并行产出最终合成完整网页 PPT。

## 08-auto-recording · 自动播放与录屏成片

信息池：
- SRT cue 183-202，时间范围 `00:04:29.600` 到 `00:05:00.133`。
- 打开本地预览地址，开启自动播放模式；本质还是网页。
- 录屏选择 16:9 区域，把系统声音录进去。
- 核心机制是用音频驱动网页播放：说到这句话展示对应文案，说到下一句切到另一个卡片或动画。

Step 切分：

1. 本地预览：localhost 预览地址打开，`?auto=1` 开关点亮。
2. 网页本体：强调它本质是网页。
3. 16:9 裁切：录屏框吸附到固定舞台。
4. 系统声音：录屏 HUD + 音量 meter。
5. 音频驱动：playhead 拉动页面状态点。
6. Cue 触发卡片：上一句展示当前卡片，下一句切换另一张卡片/动画。
